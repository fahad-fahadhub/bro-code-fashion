# Bro Code Fashion: website codebase

A one-page online shop for Bro Code Fashion (men's casual wear, Bengaluru). A customer picks a tee and size, checks the order summary, taps **Confirm order**, and WhatsApp opens to 8296889214 with the whole order already written. There is no payment step on the site.

The site is plain HTML, CSS and JavaScript with no framework and no server. One Python script (`build_site.py`) writes the pages. The finished site is the `website/` folder: upload it to any static host.

Version 1.0, built 4 November 2026. Product requirements are in the separate PRD document; growth ideas are in the separate growth plan.

## Folder map

| Path | What it is |
| --- | --- |
| `website/` | The finished site, ready to upload. Generated by `build_site.py`. |
| `build_site.py` | The generator: page HTML, product list, settings, policy text, SEO tags. |
| `src/app.js` | All behaviour: product view, bag, checkout, WhatsApp message, motion. |
| `src/app.css` | All styling: the "Drop Mode" look, layout, dialogs, reduced-motion rules. |
| `assets/` | Fonts (`fonts/`), web images (`img/`) and hero videos (`video/`). Copied into `website/`. |
| `static/` | Icons, favicon and the sharing image. Copied into the root of `website/`. |
| `pipeline/` | Optional: turns the original photos into the site's images and video. |
| `pipeline/originals/` | The 10 original stock photos used for the tees. |
| `tests/` | Browser tests for the order flow and an accessibility check. |
| `READ-ME-FIRST.txt` | Plain-English steps for the owner: put it online, set prices, connect a domain. |

## Quick start

You need Python 3.10 or newer. Nothing else is needed to rebuild the site.

```bash
python3 build_site.py                       # writes website/ (no domain yet)
python3 build_site.py https://yourdomain.com  # with a domain: adds canonical tags, sharing URLs, sitemap
python3 build_site.py --fresh               # ignore any prices or handles edited in website/ and reset to defaults
python3 -m http.server 8123 -d website      # preview at http://localhost:8123
```

**Your edits survive a rebuild.** Before it rewrites `website/`, the script reads the old `website/assets/js/config.js` and keeps the prices, sizes, Instagram handle, email and analytics IDs. Use `--fresh` to start from the defaults in `build_site.py`.

## How the site works

- **Settings** live in `website/assets/js/config.js` (`window.BCF`): WhatsApp number, prices, sizes, Instagram, email, Google Analytics 4 and Meta Pixel IDs, and the product list. `build_site.py` writes it from the `CONFIG` dictionary. A price of `null` shows "Price on WhatsApp".
- **Shop flow** is in `src/app.js`: `openProduct` and `paintProduct` (product view), `addLine`, `setQty`, `totals` and `render` (bag), `openCheckout`, `validate` and `rules` (form checks), `buildMessage` and the form's submit handler (WhatsApp order).
- **WhatsApp order**: the submit handler builds `https://wa.me/918296889214?text=<message>` and opens it. If a pop-up is blocked, the confirmation view shows the message with an Open WhatsApp button and a Copy button.
- **Browser storage** holds three items, all wrapped in try/catch so the site still works if storage is blocked: `bcf_cart_v1` (the bag), `bcf_cust` (the customer's details) and `bcf_last` (the last order).
- **Reply status** ("Replying now" between 9 AM and 9 PM IST) is computed in the browser.
- **Analytics** loads only if `ga4` or `metaPixel` is filled in. Events: `view_item`, `add_to_cart`, `view_cart`, `begin_checkout`, `generate_lead`.
- **Motion** respects `prefers-reduced-motion` and data saver. The hero video loads after first paint.

## Everyday changes

| I want to | Do this |
| --- | --- |
| Set prices, Instagram, email, analytics IDs | Edit `website/assets/js/config.js`, then upload `website/` again. |
| Connect a domain | Run `python3 build_site.py https://yourdomain.com`, then upload `website/`. |
| Change the WhatsApp number | Edit `PH_TEL`, `PH_DISP` and `WA` at the top of `build_site.py`, then rebuild. |
| Change wording on the page | Edit the text inside `index()` in `build_site.py` (the policy pages are `PRIV`, `TERMS`, `SHIP`), then rebuild. |
| Change colours, spacing, type | Edit the colour and type variables in the `:root` block of `src/app.css`, then rebuild. |
| Change the order message | Edit `buildMessage` in `src/app.js`, then rebuild. |
| Add a tee | See below. |

### Add a tee

1. Put the photo in `pipeline/originals/` and add it to `SRC` in `pipeline/grade.py` with the box that covers any corner mark (an empty list if none).
2. Add its crop box or boxes to `V` in `pipeline/crops.py`.
3. Run `clean_originals.py`, `up.py` and `export_images.py` (see the next section).
4. Add a line to `PRODUCTS` in `build_site.py`: id, name, colour, views, description.
5. Run `python3 build_site.py`, then check the new card and its product view in the browser.

## Rebuilding the photos and video (optional)

The shipped `assets/` and `static/` are already built. You only need these steps to change the photos, the hero video or the icons.

Install once: `pip install numpy opencv-contrib-python pillow playwright`, then `playwright install chromium`, and install `ffmpeg`. Run `cd pipeline && npm install` only if you want to refresh fonts or run the accessibility test.

| Step | Command | Output |
| --- | --- | --- |
| 1 | `python3 pipeline/clean_originals.py` | `pipeline/clean/<tee>.png`, corner marks painted out |
| 2 | `python3 pipeline/up.py` | `pipeline/up/<tee>-<view>.png`, cropped and enlarged 2x with the FSRCNN model, true colour |
| 3 | `python3 pipeline/hero.py all` | `assets/video/hero-1080.mp4` and `hero-720.mp4` (portrait). This takes a few minutes. |
| 4 | `python3 pipeline/export_images.py` | `assets/img/*.webp`: product photos, graded mood images, video posters |
| 5 | `python3 pipeline/brand.py` | `static/`: app icons, favicon, 1200 x 630 sharing image |
| 6 | `python3 build_site.py` | `website/` |

Re-exported images match the shipped ones in size to within a pixel but not byte for byte, so file sizes differ slightly. Run step 3 before steps 4 and 5, because the posters and the sharing image are taken from the hero video.

## Tests

Start the preview server first (`python3 -m http.server 8123 -d website`).

- `python3 tests/test_site.py`: opens a tee, adds sizes, checks the empty-form errors, fills the checkout, confirms, and prints the WhatsApp message and any console errors.
- `python3 tests/shot_scroll.py`: scrolls the whole page at desktop and phone width and saves contact sheets to `tests/out/`.
- `python3 tests/a11y_axe.py`: runs the axe-core accessibility checker on the home page. Needs `cd pipeline && npm install` first.

On 7 November 2026, with this exact package: the build reproduced the previous `website/` byte for byte; steps 1 and 2 reproduced the earlier images pixel for pixel; the order flow ran with no console errors and produced the message shown in the PRD; axe-core reported 0 violations on the home page. Step 3 was test-rendered at small size only; the shipped videos were rendered earlier with the same code. Lighthouse and Safari and Firefox checks have not been run.

## Deploy

Upload `website/` to Netlify Drop (app.netlify.com/drop), Cloudflare Pages, or any static host. `website/_headers` sets security and cache headers on Netlify and Cloudflare. `READ-ME-FIRST.txt` has the steps in plain English.

## Known limits

- No online payment, accounts, stock counts or admin panel. Orders exist only when the customer sends the WhatsApp message.
- Product names, colours and descriptions were written from the photos and are not confirmed by the owner. Sizes S, M, L and XL are an assumption.
- The privacy, terms and shipping and returns pages are plain-language drafts. They need the owner's real rules and a legal check.
- Designs that use other companies' trademarks were deliberately left out.
- Women's ethnic wear has no photos yet, so its card is an illustration with an Ask on WhatsApp button.
